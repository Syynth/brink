Order is authorship — the .binder.json sidecar
Adapted from celeris (spine-space decision 1: "host-ordered everywhere; there is no alphabetical mode as a design driver"). Drag-to-reorder always works; the sidecar records it.
.binder.json — at the project root, committed 
{
  "order": {
    "": ["codetta.ink", "story/",
         "clues/", "menus/", "lib/"],
    "menus/": ["title.ink", "game_menu.ink",
                "options.ink"]
  },
  "folders": ["drafts/"]
}
The rules (celeris-proven)
1 Per-container order. One key per container ("" = root); values are child ids in display order. Folder ids carry a trailing slash.
2 Listed first, then the fallback. Stored ids render in saved order; anything unlisted follows — entry first, folders before files, then alphabetical. A missing sidecar IS the fallback.
3 Re-keyed on rename/move. A folder rename rewrites every affected key and id in one pass — the order survives reorganization.
4 Empty folders become real. The folders list names directories with no files yet — created in-app, they render immediately and survive reloads.
5 Invisible to the compiler. .json is not a source file (is_source_file), so the sidecar can never affect a compile — by construction, not by convention.
6 Corrupt = fallback, never an error. Same posture as recents.json: display order is cached authorship, not authored content — self-heal and move on.
