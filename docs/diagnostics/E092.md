# E092

## Summary

A `#@public`/`#@private` override that restates the module's default (e.g. `#@public` in an undeclared module, `#@private` in a declared one) — redundant, no effect (warning, modules-spec §4/§7).

## Explanation

`brink-analyzer::manifest::insert_symbol`'s `effective_visibility` applies
declaration-flips-default (`docs/modules-spec.md` §4): a declared module
(`#@module(name)` present) defaults `Private`; an undeclared stem-module
defaults `Public`. An explicit `#@private`/`#@public` override that names
exactly that default changes nothing — the effective visibility is the same
either way — so it warns rather than silently doing nothing.

## Example

```ink,fires(E092)
== ambush ==
#@public
Hi
-> DONE
```

The file declares no module, so the default is already `Public` — the
`#@public` above `ambush` restates it.

## Fix

An auto-fix (`RedundantVisibilityFixer`,
`crates/internal/brink-ide/src/redundant_visibility_fix.rs`, issue #3424,
`docs/autofix-spec.md` §9) deletes the redundant directive line entirely —
including any leading indentation on that line, so a `    #@public` doesn't
leave stray whitespace glued to what follows:

```ink,contrast
== ambush ==
Hi
-> DONE
```

This is `Applicability::Safe`: a `#@…` tag directive is consumed at compile
time and never reaches runtime tag output
(`hir::lower::directive`'s own module doc), and it is never a translatable
content line, so deleting one changes neither the program's trace nor its
exported line table. Removing the override also does not change the
*resolved* visibility the analyzer computes for the definition — the
module default takes over and computes the identical value the override
already named.

The fixer offers nothing when:

- the file is a native `.brink` source. Native's visibility marker is the
  `pub` keyword (issue #1582), not a `#@` tag directive, so there is no
  tag-line shape here to remove. On the `ProjectDb`/compile roads this
  diagnostic cannot even fire on a native file today — a `.brink` file's
  module is always `declared` (`brink_db::queries::module_map_query`),
  which defaults `Private`, so native's own `pub` mark is always a real
  override, never a redundant restatement — but the fixer still checks the
  file's dialect first, unconditionally, since everything else here only
  ever parses with the ink grammar. (A narrower harness road — direct
  `lower_native::lower` over a single file with no `module { }` wrapper,
  used by `hir::emit_native`'s and `brink-respell`'s own round-trip
  tests — *can* raise `E092` on native source: that harness always sees an
  undeclared module, so a top-level `pub` there is a real redundant
  restatement. Neither the editor nor `brink compile` reach that road.)
- two visibility directives are stacked on the same declaration (itself
  also a conflict, `E093`) — `visibility_from_directives` resolves that by
  keeping the first occurrence, and the fixer declines rather than guess
  which line the diagnostic means.
- an `@[public]`/`@[private]` annotation-channel mark sits anywhere in a
  knot/stitch's leading run, alone or alongside a `#@public`/`#@private`
  tag line. `leading_body_directives` folds an `@[…]` annotation line into
  the same directive list a `#@…` tag line lands in, and
  `visibility_from_directives` matches by name alone — so the annotation
  spelling can become the `chosen` mark or conflict with one exactly like
  the tag spelling can, but this fixer's only edit shape is deleting a tag
  line, so it declines rather than silently leave the annotation's mark in
  place (or misidentify which line is actually redundant).

A knot/stitch's leading-run scan also excludes any tag line a *following*
`VAR`/`CONST`/`LIST`/`EXTERNAL` declaration claims for itself
(`hir::lower::directive::attached_declaration`) — that line belongs to the
declaration's own lookback, not the knot/stitch's, and is left for that
declaration's own (separate) `E092` fix rather than counted toward, or
deleted as, the knot/stitch's own.
