# E092

## Summary

A `#@public`/`#@private` override that restates the module's default (e.g. `#@public` in an undeclared module, `#@private` in a declared one) — redundant, no effect (warning, modules-spec §4/§7).

## Explanation

`brink-analyzer::manifest::insert_symbol`'s `effective_visibility` applies
declaration-flips-default (`docs/modules-spec.md` §4): a declared module
(`#@module(name)` present) defaults `Private`; an undeclared stem-module
defaults `Public`. An explicit `#@private`/`#@public` override that names
exactly that default changes nothing — the effective visibility is the same
either way — so it warns rather than silently doing nothing.

## Example

```ink,fires(E092)
== ambush ==
#@public
Hi
-> DONE
```

The file declares no module, so the default is already `Public` — the
`#@public` above `ambush` restates it.

## Fix

An auto-fix (`RedundantVisibilityFixer`,
`crates/internal/brink-ide/src/redundant_visibility_fix.rs`, issue #3424,
`docs/autofix-spec.md` §9) deletes the redundant directive line entirely:

```ink,contrast
== ambush ==
Hi
-> DONE
```

This is `Applicability::Safe`: a `#@…` tag directive is consumed at compile
time and never reaches runtime tag output
(`hir::lower::directive`'s own module doc), and it is never a translatable
content line, so deleting one changes neither the program's trace nor its
exported line table. Removing the override also does not change the
*resolved* visibility the analyzer computes for the definition — the
module default takes over and computes the identical value the override
already named.

The fixer offers nothing when:

- the file is a native `.brink` source. Native's visibility marker is the
  `pub` keyword (issue #1582), not a `#@` tag directive, so there is no
  tag-line shape here to remove. In practice this diagnostic cannot even
  fire on a native file today — a `.brink` file's module is always
  `declared` (`brink_db::queries::module_map_query`), which defaults
  `Private`, so native's own `pub` mark is always a real override, never a
  redundant restatement — but the fixer still checks the file's dialect
  first, unconditionally, since everything else here only ever parses with
  the ink grammar.
- two visibility directives are stacked on the same declaration (itself
  also a conflict, `E093`) — `visibility_from_directives` resolves that by
  keeping the first occurrence, and the fixer declines rather than guess
  which line the diagnostic means.
