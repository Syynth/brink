# E190: renaming an `EXTERNAL` changes the host binding

An `EXTERNAL` function's name is the story↔engine contract: the host
registers the function by exactly that name (the external-function binding
facility, the host-capability manifest). A story-side rename compiles
cleanly and then fails at link/runtime if the engine still registers the
old name — breakage the compiler cannot see, in code the studio cannot
edit.

Renaming externals is therefore allowed but **always unsafe** (ruled
2026-08-24): the safe-rename verdict carries this entry naming the binding,
and the rename applies only through the breakage report's Force path. The
declaration and every call site are renamed together; re-registering the
engine-side function under the new name is on you.

`E190` is synthesized by the IDE's rename gate — compilation never emits
it, so no example fence can trigger it.

Builtins (`RANDOM`, …) remain non-renameable.
