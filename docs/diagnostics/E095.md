# E095

## Summary

`#@was(name)` names the thing's own *current* name — a self-alias that would be a no-op entry in the compiled alias table. Nothing to migrate; likely a stale directive left over from a previous rename (warning, modules-spec §5/§7).

## Fix

**Safe** (`docs/autofix-spec.md` §3): delete the stale `#@was(...)` tag
line. `crates/internal/brink-ide/src/stale_was_fix.rs`'s `StaleWasFixer`
offers this fix whenever `E095` fires — on a knot, a top-level or nested
stitch, a `VAR`/`CONST`/`LIST`/`EXTERNAL` declaration, and the file-level
module rename record alike.

It is mechanically `Safe`: every lowering site that reads `#@was` compares
the old name against the target's *current* name before storing anything,
so a self-aliasing occurrence never reaches the alias-table codegen (or
anything downstream of it) in the first place — `ModuleDecl.was`/the
declaration's own `was` field is left `None` for that occurrence
regardless of whether the fix runs. Deleting the tag removes a value
nothing reads, so no compiled artifact (bytecode, alias table, exported
line table) can differ. Proven by
`brink_test_harness::fix::assert_safe_fix` over `tests/fix/E095/`
(`crates/internal/brink-test-harness/tests/fix_safe_obligations.rs`).

A `#@was` naming a genuinely different old name is untouched — the fixer
only reacts to `E095` itself, never widening beyond the self-alias shape.
