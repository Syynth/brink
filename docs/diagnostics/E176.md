# E176

## Summary

A divert-with-args site (`-> knot(args)`, a tunnel call `-> knot(args) ->`, or a thread-start `<- knot(args)`) supplies a number of arguments that does not match its resolved target's declared parameter count.

## Explanation

A knot or stitch that declares parameters (`=== accuse(who) ===` in ink, `flow accuse(who) { … }` in native) is diverted to exactly like a function call: the call site must supply one argument per declared parameter. `E176` is `E031`'s sibling for this shape — `E031` is "function call argument count mismatch" and is scoped to ordinary calls (`f(args)`); `E176` covers the divert/tunnel/thread-start call shape instead, so the two can be told apart and suppressed independently.

This diagnostic was previously unreachable for a divert on either dialect, and unreachable for a native `-> knot(args)` site at all until recently:

- Before PR #2150 (issue #2136), native's `-> knot(args)` call-args syntax hard-failed with `E129` ("parses but has no HIR lowering yet") — the argument list never reached HIR at all, so no argument-checking pass could see it.
- Even after that fix wired `DivertTarget::args` for real, the arity check still could not fire: `brink_ir::symbols::project`'s divert-reference projection always recorded `arg_count: None` for a divert, regardless of how many arguments the divert actually supplied. `brink_analyzer::resolve::check_arity` (the mechanism behind `E031`) only runs when a reference's `arg_count` is `Some`, so a divert's arity was never checked on ink either, not just native. Issue #2156 closed both gaps: the reference now carries `Some(target.args.len())`, and a dedicated `E176` check runs whenever that resolves to a `Knot`, `Stitch`, or `Label`.

`E176` deliberately does **not** fire when a divert resolves through a `Variable` or a divert-typed local parameter (`=== knot(-> return_to) ===`, then `-> return_to`) — see "Advanced: sending divert targets as parameters" in the ink documentation. Those are stored/forwarded divert-target values: the variable or parameter itself carries no declared parameter row, so there is nothing meaningful to check arity against at that indirection site.

## When this fires

Any divert, tunnel call, or thread-start whose call-args argument count disagrees with the resolved knot/stitch/label's own declared parameter count — too many arguments, too few, or (bare, no parens) zero arguments against a target that declares one or more.

## Example

```ink,fires(E176)
=== accuse(who) ===
"I accuse {who}!" Poirot declared.
-> END

=== investigation ===
-> accuse("Hastings", "extra")
```

`accuse` declares one parameter (`who`), but the divert supplies two arguments — `E176`.

```brink,fires(E176)
flow accuse(who) {
  I accuse {who}!
}

flow investigation() {
  -> accuse("Hastings", "extra")
}
```

The identical shape on the native surface — `E176` fires the same way, reachable since PR #2150 wired native call-args into `DivertTarget::args`.

## Fix

Match the call site's argument count to the target's declared parameters:

```ink,contrast
=== accuse(who) ===
"I accuse {who}!" Poirot declared.
-> END

=== investigation ===
-> accuse("Hastings")
```
