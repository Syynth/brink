# E157

## Summary

An unnamed once-only choice, or an unnamed sequence (`{cycle: …}` / `{stopping: …}` / `{once: …}` / `{shuffle: …}` and combinations), carries durable visit/turn-count state with no author name to anchor its identity across edits.

## Explanation

A save's visit/turn counts key on a scope's compiled id. A **named** scope (a knot, stitch, or a choice/gather carrying an author `(label)`) hashes its id from that name — stable no matter what else in the project changes. An **anonymous** scope (an unlabeled once-only choice's target, or a sequence's wrapper container) hashes its id from *position* instead: inserting or removing a sibling construct earlier in the same **weave block** shifts every later positional counter, and with it every later anonymous id. (Counters are block-local, so an edit in one choice's body never renumbers a sibling's body — the exposure is bounded to the construct's own block. A `(label)` goes further: it anchors its entire subtree, so everything inside a labeled choice or block is independent of sibling edits anywhere.)

Issue #1674 measured this exposure and found it bounded: globals are keyed by name, so only visit/turn counts are exposed to the *runtime*, and an anonymous container's count is unreadable by author expressions (there is no way to write `READ_COUNT` against something with no name). (`docs/decision-log.md`'s 2026-07-27 "CORRECTION to the R1 entry" widens this: anonymous scopes also carry translation units, so intl is exposed too — this lint and `LoadReport::anonymous_states_dropped` still only cover the visit/turn-count half.) The fallout, when a patch shifts an anonymous id, is exactly two shapes:

- a once-only choice may **reappear**, as if never chosen;
- a sequence may **restart** from its first branch.

`brink_runtime::save::load_state` reports this after the fact through `LoadReport::anonymous_states_dropped` (a saved anonymous visit/turn count that no longer resolves). This lint is the *before*: a compile-time nudge to name the construct so the exposure never happens in the first place.

Naming is the fix ruled proportionate for choices — a labeled choice (`* (label) …`) resolves its identity by name, not position, is immune to this drift, and anchors everything inside its body along with it. A sequence has no label syntax of its own; the mitigation is structural — place it inside a `(label)`ed choice or block (whose anchor insulates it), or in its own small, stably-named stitch, so nothing can renumber it.

This lint is **off/info by default** (RULED: a single-shot project that never patches its content should not be nagged) and tier-able through `[lints]` like any other diagnostic code — a team doing live-ops or shipping user-generated content can raise it:

```toml
[lints]
E157 = "warn"   # or "deny", "hint" — any LintLevel
```

Only constructs that genuinely carry durable state are flagged:

- a `+` (sticky/repeatable) choice is never flagged — it has no "already chosen" state to begin with;
- a fallback (`else`) choice is never flagged;
- a single-branch, non-`once` sequence is never flagged — its computed branch index is always `0` regardless of visit count, so despite the alternation syntax it is genuinely stateless.

## Example

```ink,fires(E157)
=== forest ===
* [Look around] You see nothing new.
    -> forest.done
- (done)
    -> DONE
```

The `* [Look around]` choice has no `(label)`. If a later edit adds another choice above it in the same knot, the choice's compiled identity shifts and a save made before the edit will show it as available again, even though the player already chose it.

## Fix

Give the choice a stable identity with a label:

```ink,contrast
=== forest ===
* (look_around) [Look around] You see nothing new.
    -> forest.done
- (done)
    -> DONE
```

A sequence has no label syntax at all (`anonymous_stateful.rs`'s own module doc: "there is no label syntax for a sequence at all, unlike a choice") — so `E157` fires for **every** multi-branch (or single-`once`-branch) sequence unconditionally, and no amount of restructuring silences it. Isolating the sequence in its own small, dedicated stitch does not stop the warning, but it does eliminate the actual exposure the warning exists to flag: nothing else shares that stitch's scope, so no sibling insertion anywhere else in the project can ever shift this sequence's positional id. The warning is intentionally conservative (a purely syntactic check, not a "provably safe" analysis) — isolating the sequence is still the right response, it just does not make `E157` stop firing:

```ink,fires(E157)
=== forest ===
-> forest.narration
= narration
{&You see a fox.|You see a deer.|You see nothing.}
-> DONE
```
