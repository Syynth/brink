# E154

## Summary

An `@[allow(…)]` names a real diagnostic code that is **not suppressible**: one whose default severity ([`DiagnosticCode::severity`]) is `Error`.

Source-level suppression only ever reaches the warning/lint tier. An error means the compiler cannot produce a correct artifact, so letting an annotation silence one would be a way to ship broken code; the B0.3 admission-validator family (`E121`–`E128`) is covered by the same rule (all `Error`-severity) *and* structurally, since admission diagnostics never route through [`crate::suppressions::apply_suppressions`] at all. This mirrors the `[lints]` table's own hard-error exemption: rather than curating which `Error` codes are "safe" to relax, none of them are reachable.
