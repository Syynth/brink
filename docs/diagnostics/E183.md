# E183

## Summary

A call site's resolved target is a symbol kind that cannot be called — the compiler names the kind it actually found (`ListItem`, `Label`, `Stitch`, `Param`, `Temp`, or `Struct`) rather than silently emitting a call against it.

## Explanation

`lower_call` (`brink-ir::lir::lower::expr`) turns a resolved call-site symbol into LIR. Most resolved kinds have an explicit lowering (`External` → `CallExternal`, `List` → a list-conversion builtin, `Variable`/`Constant` → `CallVariable`, `Knot` → `Call` — ink allows any knot as a function via tunnels, so no other kind needs its own arm to be *legitimately* callable). Every other kind reaching this point is not callable, and this code refuses it with a diagnostic instead of falling through a catch-all that would emit `lir::Expr::Call` against whatever id happens to be resolved there.

That catch-all used to exist with no check at all (issue #2837). It is exactly the mechanism that let a resolution bug in PR #2836's first attempt ship as a silent miscompile: the program compiled clean — 7,941 tests, the oracle ratchet, and clippy all green — and then faulted at runtime with `UnresolvedDefinition(ListItem(..))`. The reason a resolution mistake became a *runtime* fault instead of a *compile* error was this unguarded catch-all, not the specific resolution bug that first exposed it (that one was fixed separately, in `brink-analyzer::resolve::resolve_function`). This code is the backstop: whatever puts a non-callable symbol at a call position in the future, the compiler refuses it here rather than shipping it.

`resolve_function` cannot legitimately hand back `Stitch`, `Label`, or `Struct` for a real call site today, and a bare `ListItem` only ever comes back for a `#fn(target)` literal site (`arg_count: None`), which never reaches `lower_call` at all — those four kinds are a defensive backstop against a future resolution regression. `Param`/`Temp` are different: they are reachable from ordinary author source today, whenever `LowerCtx::temp_slot` has nothing open for the name at the call site — the normal shape of a genuine forward reference, not a `temp_slot` bug (see "When this fires" below).

## When this fires

- A call site's path resolves (via the same resolution map `lower_call` keys its lookup on) to a `ListItem`, `Label`, `Stitch`, or `Struct` definition instead of something callable — analyzer-unreachable from real source today; a defensive backstop.
- A call to a `temp`/param name used before its own declaration (a genuine forward reference) — reachable from ordinary source on both the `.ink` and `.brink` surfaces, no `--dialect brink` needed. Example: `~ f()\n~ temp f = 1`.

## What does NOT fire

- A call to a declared `EXTERNAL`, a list-conversion call (`list(n)`), a variable/constant holding a divert target, or a knot used as a function (`== function foo ==`, or any knot called via ink's tunnel-as-function convention) — all have their own lowering. A stitch reached via direct-call syntax does not reach this diagnostic either, but for an unrelated reason: it never reaches `lower_call`'s resolved-target match at all (it ends earlier, at `E104`/`E025`).
- A `#fn(target)` literal naming a bare list item — that is a fn-value reference, not a call site, and never reaches this check.
- Calling a T1b block-scoped temp (`~ { … }`) after its own block has closed — that is [E082](E082.md), the identical guard `lower_path` already applies for the same read-after-close mistake, not this diagnostic.

## Example

A forward reference at a call position reaches this diagnostic on real, author-writable source — no hand-constructed resolution map needed:

```ink
~ f()
~ temp f = 1
```

reports `E183: \`f\` is used here before its declaration — it is not in scope at this call site`, on both the plain `.ink` surface and `--dialect brink`.

The `ListItem`/`Label`/`Stitch`/`Struct` arms remain the genuinely-backstop part of this diagnostic: the analyzer's own resolution never legitimately hands `lower_call` one of those four kinds for a real call site (see Explanation). That part is exercised directly in `brink-ir`'s own lowering tests by handing `lower_call` a hand-constructed resolution map that points a call site at a non-callable symbol (`crates/internal/brink-ir/tests/lir_lowering/non_callable_call_target.rs`), reproducing the shape of the bug PR #2836 exposed. The forward-reference and closed-block-scope-call shapes above need no such simulation — they are covered by ordinary compile-level tests in the same file.

## Fix

For a forward reference, move the `temp`/param declaration above its first use, or rename the call target. For the `ListItem`/`Label`/`Stitch`/`Struct` backstop arms, this code should never fire against real source — if it does, the bug is upstream, in whatever resolution pass (`brink-analyzer::resolve` or a future rewrite) put a non-callable symbol at a call-site position. Fix the resolution, not the call site.
