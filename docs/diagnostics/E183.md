# E183

## Summary

A call site's resolved target is a symbol kind that cannot be called — the compiler names the kind it actually found (`ListItem`, `Label`, `Stitch`, `Param`, `Temp`, or `Struct`) rather than silently emitting a call against it.

## Explanation

`lower_call` (`brink-ir::lir::lower::expr`) turns a resolved call-site symbol into LIR. Most resolved kinds have an explicit lowering (`External` → `CallExternal`, `List` → a list-conversion builtin, `Variable`/`Constant` → `CallVariable`, `Knot` → `Call` — ink allows any knot as a function via tunnels, so no other kind needs its own arm to be *legitimately* callable). Every other kind reaching this point is not callable, and this code refuses it with a diagnostic instead of falling through a catch-all that would emit `lir::Expr::Call` against whatever id happens to be resolved there.

That catch-all used to exist with no check at all (issue #2837). It is exactly the mechanism that let a resolution bug in PR #2836's first attempt ship as a silent miscompile: the program compiled clean — 7,941 tests, the oracle ratchet, and clippy all green — and then faulted at runtime with `UnresolvedDefinition(ListItem(..))`. The reason a resolution mistake became a *runtime* fault instead of a *compile* error was this unguarded catch-all, not the specific resolution bug that first exposed it (that one was fixed separately, in `brink-analyzer::resolve::resolve_function`). This code is the backstop: whatever puts a non-callable symbol at a call position in the future, the compiler refuses it here rather than shipping it.

`resolve_function` cannot legitimately hand back `Stitch`, `Label`, or `Struct` for a real call site today, and a bare `ListItem` only ever comes back for a `#fn(target)` literal site (`arg_count: None`), which never reaches `lower_call` at all. `Param`/`Temp` are listed as a defensive backstop too — `LowerCtx::temp_slot` is expected to intercept every local before resolution is even consulted (the same backstop posture `lower_path`'s own `SymbolKind::Temp` fallback arm takes) — so every kind this code can currently report is either analyzer-unreachable in production or a slot `temp_slot` failed to catch first.

## When this fires

- A call site's path resolves (via the same resolution map `lower_call` keys its lookup on) to a `ListItem`, `Label`, `Stitch`, `Param`, `Temp`, or `Struct` definition instead of something callable.

## What does NOT fire

- A call to a declared `EXTERNAL`, a list-conversion call (`list(n)`), a variable/constant holding a divert target, or a knot/stitch used as a function (`== function foo ==`, or any knot called via ink's tunnel-as-function convention) — all have their own lowering.
- A `#fn(target)` literal naming a bare list item — that is a fn-value reference, not a call site, and never reaches this check.

## Example

There is no author-writable `.ink`/`.brink` program that reaches this diagnostic today — the analyzer's own resolution never legitimately hands `lower_call` one of these kinds for a real call site (see Explanation). It exists as a defensive backstop against a *future* resolution regression, exercised directly in `brink-ir`'s own lowering tests by handing `lower_call` a hand-constructed resolution map that points a call site at a non-callable symbol (`crates/internal/brink-ir/tests/lir_lowering/non_callable_call_target.rs`), reproducing the shape of the bug PR #2836 exposed.

## Fix

This code should never fire against real source. If it does, the bug is upstream — in whatever resolution pass (`brink-analyzer::resolve` or a future rewrite) put a non-callable symbol at a call-site position. Fix the resolution, not the call site; the call site's `.ink`/`.brink` source is not necessarily wrong.
