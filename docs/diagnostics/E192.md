# E192: unrecognized `brink-` directive comment

A comment starting `brink-` that the suppression parser does not recognize
suppresses nothing. It is reported rather than ignored, because a directive
that silently does nothing is indistinguishable — from the author's side —
from one that works.

This is what made #3259 invisible. `// brink-disable-file E157` looks exactly
like the line-scoped `// brink-disable E157`, which does take codes. The
file-scoped form did not, so the comment matched no branch, suppressed
nothing, and said nothing.

## The directives that exist

| Directive | Scope |
|---|---|
| `// brink-disable-all` | every diagnostic, whole project (root file only) |
| `// brink-disable-file-all` | every diagnostic in this file |
| `// brink-disable-file E027 E035` | those codes, whole file |
| `// brink-disable` | every diagnostic on the next line |
| `// brink-disable E027 E035` | those codes, next line |
| `// brink-expect E027` | as `disable`, and errors if the code does not appear |

Codes are separated by whitespace, in every form that takes them.

## Example

```ink,fires(E192)
// brink-disable-file
=== start ===
Hello.
-> END
```

A bare `// brink-disable-file` named no codes. Before #3259 it silenced the
whole file; that meaning now belongs to `// brink-disable-file-all`, so this
form is incomplete rather than blanket.

## Fixing it

Name the codes you meant:

```ink,contrast
// brink-disable-file E027
=== start ===
Hello.
-> END
```

or say you meant all of them:

```ink,contrast
// brink-disable-file-all
=== start ===
Hello.
-> END
```

Both are `contrast` fences: they compile, and `E192` must be absent from
what they produce. A spelling that stopped working would fail this page
rather than quietly becoming wrong advice.
