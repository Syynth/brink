# E084

## Summary

A struct construction literal (`Name#{…}`) supplies the same field name more than once. Previously a silent last-wins: only the final initializer's value was placed, and — because the well-formed `RecordNew` lowering path discarded every non-placed lowered expression tree wholesale — an earlier duplicate's initializer (including any observable side effect, e.g. a function call) never actually ran at all, with no diagnostic. Now a real compile error naming the repeated field, under both `types = gradual` and `types = strict` — unlike `E069`/`E070`/ `E071` (which need a resolved shape to check missing/extra/mistyped fields against, and are strict-mode-only), a duplicate field is a structural authoring mistake detectable from the literal alone, independent of type-checking policy or whether the shape name even resolves.
