# E143

## Summary

**D5**: `recv.name(args)` resolved to a free function whose first parameter is declared `ref`, so the receiver is auto-ref'd (`party.leader.heal(5)` → `heal(ref party.leader, 5)`, issue #1462) — but *this* receiver cannot be written through: a `CONST`, a frame-local projection more than one field deep, or — once the grammar can spell them — an rvalue such as `[1,2].push(3)`. Refused rather than silently desugared by value, which would drop the mutation. A non-`ref` first parameter never reaches this code: the by-value desugar puts no lvalue requirement on its receiver.

A projection whose root is a frame-local (`let g = Guest { … }; g.hp.heal(5)`) is **legal**, one field level deep (**RULED 2026-07-27**, issue #1531): a frame-local cell is a valid projection root, and the mutation needs no effect row because it is unobservable outside the frame. This is a *statement*-position construct only — the same call nested inside a larger expression (e.g. `let unused = g.hp.heal(5);`) still refuses with E143, because the lowering that makes the frame-local case work is a statement-level read/call/write-back expansion with no expression-shaped equivalent. A projection whose root is durable (a `VAR`) remains legal at any depth, in either position, per T1e's durable-root rule (`docs/t1e-spec.md` §2).
