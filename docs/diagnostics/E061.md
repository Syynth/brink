# E061

## Summary

A type annotation names something that isn't a recognized nominal type (`int`/`float`/`bool`/`string`/`divert`/`void`), a `List<L>` naming a declared `LIST`, `Array<T>`, `Map<K, V>`, `Option<T>`, `Weighted<T>`, or `Handle<K>` — declared struct names arrive in TM-4. Since issue #2272, a declared struct name can also raise `E061` when it is declared somewhere in the project but not reachable from the referring file — the diagnostic then names the module the struct lives in, rather than the generic "unrecognized type" message.

## Explanation

[Detailed explanation of this diagnostic, why it occurs, and what it means for your code.] A bare struct-name annotation is checked against the same referrer-scoped `ImportScope`/import-visibility rules an ordinary reference is, so a struct declared in a module this file has not imported does not count as "recognized" even though the name exists elsewhere in the project.
