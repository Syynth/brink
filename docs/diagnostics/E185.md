# E185

## Summary

A plain dotted assignment target (`~ p.bogus = expr`) names a field its receiver's resolved struct shape doesn't declare — the `E070` mirror for a construction-literal's own unknown-field check, applied to `Stmt::Assignment`/`BlockStmt::Assignment` targets instead of a `#{...}` literal.

## Explanation

Issue #1900 (PR #1939) added strict-mode type checking for a plain dotted-assignment target's *value* against the field's declared type — `check_declared_field_assign_target` records a candidate fact for `~ p.x = expr`, later walked by `structs::check_field_assign_mismatch` against the receiver's declared shape to compare `expr`'s type with `x`'s declared type (`E063` on a mismatch). That check is deliberately silent when the field name itself doesn't resolve on the shape — "Unknown never disagrees" is its posture, by design, for the *type-mismatch* comparison.

But that left a real gap: nothing checked whether the field name *exists* on the shape at all. `ref_projection::check_strict`'s `E098` covers an unknown segment only in `ref`-argument position (`ref npc.bogus`, handed to a call); the construction-literal path already had this check (`structs::check`'s `E070`, `docs/typed-mode-spec.md` §6) but only for `Point#{bogus: 1}`-shaped literals. A plain assignment to an unknown field had no equivalent, and compiled clean under `types = strict` with zero diagnostics.

`E185` closes that gap: `structs::check_field_assign_mismatch` (the same function `E063` comes from) now reports it the moment the walk resolves the receiver's shape but the shape declares no field by the name being assigned.

## When this fires

- The assignment target is a single-level dotted path (`p.field = expr` — LIR's own `try_lower_field_assignment` boundary; `p` alone or `p.a.b` never reach this check at all, see "What does NOT fire" below).
- The root (`p`) has a **statically resolved** type — a `VAR`/`CONST` declaration's own type, or an annotated `Param`/`Temp` — that is a known `STRUCT` shape.
- That shape does **not** declare a field with the target's name.
- `types = strict` (this check, like `E063`/`E069`–`E071`, only ever runs under strict).
- `dialect = brink` — `STRUCT` is a brink-dialect extension (`E051` under `strict ink`), and `types = strict` itself requires `dialect = brink` (`E064`); an `.ink` file under `dialect = strict ink`/`ink` can never reach this check at all, regardless of its `types` policy.

## What does NOT fire

- **An untyped/unresolved receiver.** If `p`'s type never resolves past `Ty::Unknown` — an unannotated function parameter with no declared type is the genuine case, since there is truly no shape anywhere to resolve it against — the walk never reaches the field-name check at all — it returns silently the moment the root isn't a resolved `Ty::Struct`. "Unknown never disagrees" holds for the receiver exactly as it does for `E063`: the analyzer has no shape to check the name against, so no diagnostic is possible.
- **An unannotated `~ temp` initialized from a struct literal** (`~ temp p = Point#{x: 0.0}` then `~ p.bogus = 1`) also stays silent — but not because no shape exists. The shape *is* statically knowable from the initializer; `check_declared_field_assign_target` only ever reads the root's type from `self.annotated`/`ctx.globals` (an explicit ascription or a global's declared type), never an unannotated temp's locally-inferred type. This is a limitation of the recording site, not an instance of "no shape to check the name against" — closing it is future work, out of this diagnostic's scope. An *annotated* `~ temp p: Point = …` does resolve and does fire `E185`, same as a `VAR`.
- **A chained target** (`o.i.a = expr`, 3+ segments). `check_declared_field_assign_target` fences itself at exactly `p.segments.len() == 2` — a longer chain never gets a candidate fact recorded at all, because LIR's own `try_lower_field_assignment` rejects it outright with the non-suppressible `E074`, regardless of whether the field name exists or the RHS's type agrees. Reporting `E185` (or `E063`) for a construct that's rejected either way would tell the author to fix something that stays rejected.
- **A field that resolves but disagrees in type**, not name — that's `E063`, not `E185`.
- `types = gradual` or unset — like every other strict-only struct-shape check in this module, `E185` never fires outside `types = strict`.

## Example

```brink
STRUCT Point = #{x: float, y: float}
VAR p: Point = Point#{x: 0.0, y: 0.0}
=== main ===
~ p.bogus = 1
-> DONE
```

reports `E185: plain assignment target names a field its struct shape does not declare: \`Point\` has no field \`bogus\`` under `types = strict`.

By contrast, an untyped receiver stays silent even with the same unknown field name:

```brink
=== function f(p) ===
~ p.bogus = 1
-> DONE
```

`p` has no declared type here, so its type never resolves past `Ty::Unknown` — no diagnostic, matching the same "Unknown never disagrees" posture every other shape-agreement check in this module takes.

## Fix

Rename the assignment target to a field the shape actually declares, or add the field to the `STRUCT` declaration if it was meant to exist.
