# E119

## Summary

A pure-callback verb's callback provably breaks the pure·silent contract. Two verb families carry this code, because the 2026-07-18 sitting ruled both:

- `sort_by`/`sorted_by` comparators (§4b: "the comparator falls under the trio's pure·silent rule plus the consistent-total-order LAW");
- the fn-value verb layer's pure quartet `map`/`filter`/`fold`/`filter_map` (§4, issue #1679) — pure-required is what makes iteration order unobservable. The ruled effectful spellings `each`/`map_each` (issue #1679 slice 2) are the legal home for callbacks that need effects, and are deliberately not gated by this code.

Exceedance-only, the E114 posture: flagged when the callback is a statically-named `#fn(target)` literal (ink/brink), or — since issue #1887, #1862's 2026-08-01 ruling — its native bare-name equivalent (`map(items, double)`, no sigil) whose inferred row shows a global read/write, an external call, a content emission, or a tag touch — an opaque or unresolvable callback is not *proven* in violation and passes (the gradual posture; the VM's isolation and `ComparatorEscaped` fault are the runtime residual). Purity still cannot be enforced *through* a fn value: `Ty::Fn` carries an effect row since #1680 step 3, but no inferred type is threaded into this gate and effects-spec §6.1c's stratum question is open. Tracked on issue #1679. An inline lambda argument is a separate, still-open hole (issue #1887 scope, deferred to #1709/#1727 — a lambda has no `DefinitionId` until LIR lowering).
