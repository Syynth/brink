# E119

## Summary

A pure-callback verb's callback provably breaks the pure·silent contract. Two verb families carry this code, because the 2026-07-18 sitting ruled both:

- `sort_by`/`sorted_by` comparators (§4b: "the comparator falls under the trio's pure·silent rule plus the consistent-total-order LAW");
- the fn-value verb layer's pure trio `map`/`filter`/`fold` (§4, issue #1679) — pure-required is what makes iteration order unobservable. The effectful spellings `each`/`map_each` are the ruled home for callbacks that need effects (not shipped yet).

Exceedance-only, the E114 posture: flagged when the callback is a statically-named `#fn(target)` whose inferred row shows a global read/write, an external call, a content emission, or a tag touch — an opaque or unresolvable callback is not *proven* in violation and passes (the gradual posture; the VM's isolation and `ComparatorEscaped` fault are the runtime residual). See issue #1680: `Ty::Fn` carries no effect rows, so purity cannot be enforced *through* a fn value at all today.
