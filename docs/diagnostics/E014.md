# E014

## Summary

Logic line has no effect (bare `~`).

## Explanation

A `~` logic line that lowers to no statement at all: not a `~ temp`
declaration, not an assignment, not a `return`, not a `~ { … }` block, not
an `await`, and not even a bare expression — just `~` followed by nothing
the grammar recognizes as the start of one. The line contributes nothing to
the compiled program, so the compiler flags it rather than silently
dropping it.

`E014` also covers a handful of unrelated **malformed** partial parses that
happen to share the code — fourteen other raise sites in total, across
three files: `~ temp` and `~ x =` (target/value) shapes with a missing
name or value in `hir::lower::content::logic_line`, the `~ { … }`
block-statement mirrors (`TempDecl`/`Assignment`/`ForStmt`) in
`hir::lower::content::logic_block`, and the native surface's own
`let`/`assign`/`for` mirrors missing their name, place, or value in
`hir::lower_native::control_flow`. Those are error-recovery diagnostics
over a real, if broken, construct — not an empty line — and the auto-fix
below is careful to tell the two apart.

## Example

```ink,fires(E014)
VAR score = 0
Hello.
~
~ score = score + 1
Score is {score}.
-> DONE
```

The bare `~` on its own line — line 3 — has no effect at all and raises
`E014`. The following line, `~ score = score + 1`, is an ordinary
assignment and raises nothing.

## Fix

An auto-fix deletes the effect-free `~` line (and its line break) entirely
— issue #3423, `docs/autofix-spec.md` §9's first-wave `Safe` candidate
("E014 bare `~` → delete the line"). It is `Applicability::Safe`: the line
contributes nothing to the compiled program, so removing it cannot change
the program's observable behaviour.

```ink,contrast
VAR score = 0
Hello.
~ score = score + 1
Score is {score}.
-> DONE
```

The fixer (`crates/internal/brink-ide/src/empty_logic_line_fix.rs`)
re-derives effect-freedom from the CST itself rather than trusting the
diagnostic: it only offers the deletion when the located logic line carries
none of the five recognized statement kinds (`~ temp`, an assignment, a
`return`, a `~ { … }` block, an `await`) **and** has no expression child
either — the same predicate the compiler's own lowering uses to decide
`E014` fires from this shape, checked independently. The `~ temp`/`~ x =`
malformed-partial sites fail that check by construction (a `~ temp = 5`
with a missing name is still recognized as a `~ temp` declaration, just an
incomplete one) and get no fix offered. The `~ { … }` block-statement
sites are excluded a different way: they diagnose at the inner
`TempDecl`/`Assignment`/`ForStmt` node's own range rather than the
enclosing logic line's, so the fixer's exact-range lookup for a logic line
never finds one there at all. Either way the result is narrower coverage
rather than a downgraded tier. A comment attached to the bare `~` line (a
trailing `// …` or a `/* … */` spanning several physical lines) also
withholds the fix outright — a comment is trivia to the parser and would
otherwise be deleted right along with the line, which is not "no effect"
for the author's own text. The fixer is ink-only: the native surface's own
"nothing after `~`" shape parses as an expression statement with a missing
operand and raises `E015` instead, never `E014` — there is no native shape
this fixer's diagnostic code is even reached for.
