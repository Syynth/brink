# E189: ink `TODO:` author note

An ink `TODO:` line marks work the author knows is still to be done. It is
not a defect — the language defines the construct precisely so unfinished
places can be marked without breaking the compile.

Until issue #3050, lowering dropped these notes silently. They now surface
as `Info`-severity diagnostics so they appear in the Problems panel and the
studio's TODO panel, and so tooling can enumerate them by code.

## Example

```ink,fires(E189)
=== start_new_game ===
TODO: minnie's letter needs a second pass — voice is too old
Minnie pressed the letter flat against the glass.
```

Every `TODO:` line produces one `E189` diagnostic whose message carries the
note's text.

Recognized wherever a `TODO:` line can appear: a knot/stitch/top-level
body, and — since issue #3353 — inside a multiline conditional's then-arm,
`- else:` arm, or a nested block:

```ink,fires(E189)
VAR ending_reached = false
{ ending_reached:
    The story concludes.
    TODO: write the epilogue
- else:
    Still going.
}
```

Before #3353, a `TODO:` inside a branch like this was parsed as ordinary
prose — it never reached `E189` and was printed to the player instead of
being suppressed.

## Severity

`Info` by default (the E157 precedent — advisory, never compile-blocking).
Like every code, it can be re-tiered per project:

```toml
[lints]
E189 = "allow"    # hide TODOs entirely — or "warn" to make them louder
```

## When you're done

Delete the `TODO:` line. Existence in source is the whole lifecycle — there
is no separate "done" state to manage.
