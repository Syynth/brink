# E031

## Summary

Function call argument count mismatch.

## Explanation

`brink_analyzer::resolve::check_arity` compares an ordinary call site's
supplied argument count against the resolved target's declared parameter
count. This is `Warning`-tier: the mismatched program still compiles and
runs — the call site's excess or missing arguments are a mechanical
problem the compiler can point at, not one that blocks the build.
`E176` is this diagnostic's sibling for a divert/tunnel/thread-start call
shape rather than an ordinary call.

## Example

```ink,fires(E031)
=== function greet(name) ===
~ return "Hi " + name

=== main ===
~ temp msg = greet("Al", "Bob")
{msg}
-> END
```

`greet` declares one parameter (`name`), but the call supplies two — `E031`.

## Fix

An auto-fix trims the call back to the target's declared argument count
(issue #3428, `docs/autofix-spec.md` §9) — but **not** by deleting the
*trailing* excess argument, which a first read of "over-supplied args"
suggests. The classic calling convention this diagnostic covers
(`Opcode::Call`/`Opcode::CallExternal`, not the `#fn(...)`/`call(...)`/
`bind(...)` function-value machinery) pushes every supplied argument in
source order and lets the callee's own parameter-binding prologue pop
its declared count off the shared value stack, LIFO — so it is the
**trailing** supplied argument that the callee actually binds, and the
**leading** excess that is silently pushed, evaluated, and never
consumed. Confirmed by running the example above: it prints `Hi Bob`,
not `Hi Al`. The mechanical, behaviour-preserving fix is therefore to
remove the leading excess argument and keep the trailing one:

```ink,contrast
=== function greet(name) ===
~ return "Hi " + name

=== main ===
~ temp msg = greet("Bob")
{msg}
-> END
```

(See `crates/internal/brink-ide/src/arity_trim_fix.rs`'s module doc for
the full account, including why this only holds for the classic call
path and not `creation_site_fix`'s `#fn(...)` trim, which keeps the
*leading* prefix instead.) The fixer withholds this rewrite entirely —
offering nothing — when any of the *leading* (dropped) arguments could
carry a side effect (a nested call or an assignment), since deleting one
would then change the program's behaviour rather than preserve it.
