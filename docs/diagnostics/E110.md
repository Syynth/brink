# E110

## Summary

The deprecated `#@effects(…)` tag-channel spelling — superseded by the `@[effects(…)]` annotation final form. Warning: the alias keeps parsing (it shipped in released surface, `@brink-lang/web@0.11.1`).

## Explanation

`#@effects(…)` was the original tag-channel spelling of a knot/stitch's effects assertion. The `@[effects(…)]` annotation is the final NS-A2 form (`docs/stdlib-spec.md` §9.2, ruled 2026-07-18), and the two spellings are **not** interchangeable text: `#@effects(…)` keeps the legacy **colon** argument grammar (`reads: gold, hp`) frozen forever, while `@[effects(…)]` uses the amended **paren-clause** grammar (`reads(gold, hp)`, 2026-07-19). The tag spelling still parses — nothing about the assertion's meaning changes — but every new definition should use the annotation spelling, and this warning is how an existing `#@effects(…)` site is found.

## When this fires

Any knot or stitch whose leading body carries a `#@effects(…)` tag-channel directive, on the ink surface. The native `.brink` surface has no such alias (`hir::lower_native::annotation` recognizes only `@[effects(…)]`), so `E110` never fires there.

## Example

```ink,fires(E110)
VAR mood = 5

-> greet

=== greet ===
#@effects(reads: mood)
Mood is {mood}.
-> END
```

`greet` declares its effects assertion with the deprecated tag spelling — `E110`.

## Fix

Rewrite the tag to the `@[effects(…)]` annotation spelling, translating the argument list from the colon grammar to the paren-clause grammar — **not** a byte-for-byte copy of the parenthesised text, which would hand the annotation parser a string in the wrong grammar (`@[effects(reads: mood)]` is itself malformed, `E101`: a bare top-level identifier is always a flag under the paren-clause grammar):

```ink,contrast
VAR mood = 5

-> greet

=== greet ===
@[effects(reads(mood))]
Mood is {mood}.
-> END
```

An **automatic**, `Safe` fix (issue #3426, `docs/autofix-spec.md` §9) performs exactly this translation: it parses the tag's argument list under the legacy colon grammar into the same `{pure, silent, total, reads, writes, calls}` shape the assertion itself carries, then renders it as paren clauses. `crates/internal/brink-ide/src/effects_tag_fix.rs`'s own fixture tests compare that parsed assertion shape before and after, read off the HIR through the real production parsers on both sides — not by trusting the fixer's own translation in isolation — and separately confirm re-analysis of the rewritten source produces no diagnostics at all.

The fix withholds itself — offering nothing rather than guessing — when the tag:

- is **dynamic** (carries an inline `{…}` logic block): directives must be static, and a text-based rewrite would silently drop the interpolated part;
- has **no argument list** at all (bare `#@effects`, or an unbalanced paren) — that is `E100`'s territory, not a rewrite;
- fails to **parse** under the legacy colon grammar (an unknown clause key, a non-identifier value, or a `pure`/clause contradiction) — that is `E101`'s territory, and a malformed author intent is not something a `Safe` fixer may guess at.
